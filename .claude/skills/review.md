# /review — Blog Post Review

블로그 글 검수 스킬. 작성한 초안을 최대 5개 에이전트가 각자 분야를 검토한다.

## 실행 방법

```
/review drafts/my-post.md
/review                      ← 인자 없으면 drafts/ 최신 파일 자동 선택
```

## 에이전트 구성 (최대 5개)

| # | 에이전트 | 항상/조건부 | 검토 항목 |
|---|----------|------------|----------|
| 1 | 글쓰기 | 항상 | 문장 구조 · 논리 흐름 · 가독성 · 도입부/결론 |
| 2 | SEO | 항상 | title · description · tags · 키워드 밀도 |
| 3 | 독자 경험 | 항상 | 타겟 독자 관점 · 이해도 · 예시 충분성 |
| 4 | 기술 정확도 | 코드/기술글 | 코드 정확성 · 기술 사실 검증 · 용어 오류 |
| 5 | 팩트체크 | 통계/주장 있으면 | 수치 · 주장 근거 · 오해 소지 |

기술글 판단 기준: 코드 블록(```) 3개 이상 또는 frontmatter tags에 기술 키워드 포함.

## 실행 절차

1. 파일 읽기 — frontmatter + 본문 전체 파악
2. 기술글 여부 판단 → 에이전트 4·5 활성화 여부 결정
3. 해당 에이전트들을 **병렬**로 실행 (Agent 툴, 각각 독립적으로 글 분석)
4. 각 에이전트 결과를 아래 포맷으로 통합 보고

## 보고 포맷

```
## 검수 결과 — [파일명]

### ✍️ 글쓰기
[소견 — 잘된 점 + 개선 필요 항목]

### 🔍 SEO
[소견]

### 👥 독자 경험
[소견]

### 💻 기술 정확도  ← 해당 시만
[소견]

### 📊 팩트체크  ← 해당 시만
[소견]

---
수정 제안:
1. [항목] — [구체적 수정 방향]
2. ...

퀴즈 생성 준비: ✅ / ⚠️ [이유]
```

## 주의

- 에이전트는 글 내용만 검토. 코드 실행이나 외부 URL 접근 불필요.
- 각 에이전트는 독립적으로 판단 — 다른 에이전트 결과 참조 금지.
- "퀴즈 생성 준비" 판단: 글이 충분히 완성되어 퀴즈 문제를 낼 수 있는 상태인지.
